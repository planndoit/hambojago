# 함보자 (Hamboja)

> “야, 한 번 보자” — 약속 날짜를 가장 빠르게 맞추는 서비스

---

## 문제 (Problem)

친구들과 약속을 잡을 때 흔한 장애:

> 날짜 맞추다가 모임이 깨진다

- 카카오톡 대화로 조율하면 메시지가 묻힘
- 누가 되는지 정리하기 어려움
- 같은 질문·답변이 반복되어 스트레스가 큼

결과적으로 모임 자체가 성사되지 않는 경우가 많음.

---

## 해결 (Solution)

함보자는 **날짜를 가장 빠르게 맞추게 해주는 서비스**다.

- 링크 하나로 공유
- 참여자는 로그인 없이 참여
- 가능한 날짜만 선택
- 최적 날짜 자동 추천

---

## MVP 목표

> **10초 안에 날짜 선택을 끝내게 한다**

---

## 사용자 역할

### 모임 생성자 (Creator)

- 약속 생성
- 링크 공유
- **로그인 필요**

### 참여자 (Participant)

- **로그인 없이** 참여
- 날짜 선택만 수행

---

## 사용자 흐름

### A. 약속 생성자

1. **첫 진입** — “약속 만들기” 버튼과 간단한 설명 (예: *10초만에 약속 날짜를 잡아보세요*)
2. **약속 만들기 클릭** → 로그인·회원가입 유도
3. 로그인·회원가입 완료
4. **약속 생성** — 이름, 설명(선택), 날짜 범위 설정
5. **링크 생성** → 카카오톡 등으로 공유

### B. 참여자 (핵심 플로우)

1. 공유 링크 클릭
2. **첫 화면** — 불필요한 설명 없이 바로 캘린더 노출  
   상단: 약속 이름, 한 줄 설명
3. **날짜 선택** — 다중 선택, 터치 친화적
4. **선택 완료** 버튼
5. **이름 + 4자리 PIN** 입력
6. 완료
7. **결과 화면** 진입

---

## MVP 핵심 기능

### 1. 약속 생성

로그인 후 생성하고 링크를 공유한다.

### 2. 날짜 선택

로그인 없이 참여하고, 가능한 날짜만 선택한다.

### 3. 결과 시각화

**즉시 피드백 예시**

- 현재 참여 인원 안내 (예: “현재 3명이 선택했어요”)
- 유력 날짜 강조 (예: “5월 12일이 가장 유력해요”)

**날짜별 상태**

- 날짜별 선택 인원 수를 단계적으로 표현 (예: 많음 → 적음)

**참여자 표시**

- 날짜별 참여자 목록

**내 선택**

- 본인이 선택한 날짜를 시각적으로 구분

---

## 날짜 선택 UI (설계 방향)

- 모바일 최적화
- **달력 UI를 메인**, 날짜 리스트는 보조

### 화면 구성 (권장 순서)

1. 약속 정보  
2. 안내 문구  
3. 달력 UI (메인)  
4. 날짜 리스트 (보조)  
5. 하단 CTA  

### 달력

- 한 달 단위 표시
- 선택·해제 토글, 선택 강조
- 월 이동

### 날짜 리스트

달력 아래에 후보 날짜만 리스트로 표시 (예: 요일 포함).

### 동기화·상태

- 달력 ↔ 리스트 선택 상태 동기화
- 선택 개수 표시 (예: “3개 날짜 선택됨”)

### 하단 CTA

- 문구: **선택 완료**
- 선택이 없으면 비활성화

## 참여자 인증·수정

### 참여 시 입력

- 이름  
- 4자리 PIN  

### 서버 데이터 구조 (개념)

**Participants**

| 필드 | 설명 |
|------|------|
| participant_id | 참여자 식별자 |
| event_id | 약속 식별자 |
| name | 표시 이름 |
| pin_hash | PIN 해시 |
| edit_token_hash | 수정 토큰 해시 |
| created_at / updated_at | 타임스탬프 |

**Availability**

| 필드 | 설명 |
|------|------|
| availability_id | 레코드 식별자 |
| event_id | 약속 식별자 |
| participant_id | 참여자 식별자 |
| date | 선택한 날짜 |

### edit_token 방식

- 참여 완료 시 `edit_token` 발급
- 클라이언트에는 **localStorage**에만 원문 토큰 저장  
  키 예시: `hamboja:event:{eventId}:participantToken`

### 재접속

1. localStorage에서 `edit_token` 확인  
2. 서버 검증  
3. 본인 데이터 로드 후 수정 가능  

### 보조 수정

- localStorage가 없을 때: **이름 + PIN**으로 수정  

### 보안 원칙

- PIN은 해시로 저장  
- edit_token도 해시로 저장  
- localStorage에는 토큰 원문만 (서버에는 해시)  
- 타인 데이터 수정 불가

## UX 원칙

1. **설명보다 행동** — 캘린더를 먼저 보여준다  
2. **입력 최소화** — 이름 + PIN만  
3. **빠른 완료** — 10초 내 완료 목표  
4. **명확한 결과** — 최적 날짜 자동 제안  

### 선택 완료 후

- 참여자 수
- 유력 날짜 강조
- 날짜별 참여자
- 내 선택 강조
